## 1. 评审目标与边界

**目标**：评估 AI-Studio 的**业务设计是否成立**——产品定位是否自洽、能力闭环是否完整、业务规则是否可运营、成本与合规是否可控，并给出按优先级排序的改进建议。

**边界（明确不做）**：

| 不做 | 理由 |
|------|------|
| 重复 `docs/review/` 已覆盖的安全/工程/文档一致性结论 | 已于 2026-09-12 完成，38 项问题（P0×8/P1×13/P2×17），本方案仅在其**未覆盖的业务维度**上补充，并在结论中做交叉引用 |
| 修改任何业务代码 | 评审与整改是两次独立授权，整改需另行批准 |
| 评价 UI 视觉与交互细节 | 属前端设计范畴，与"业务是否合理"无关 |
| 引入新技术选型建议（如换框架、上 K8s） | 超出业务合理性范畴 |

**视角差异说明**：既有评审回答"代码是否符合约定"；本次评审回答"**这套业务本身值不值得这么做**"。二者可能对同一处代码给出不同结论——例如"知识库向量模型不可更换"在工程上是合理约束，在业务上是资产迁移障碍。

## 2. 评审维度（4 个分册 + 1 个总览）

| 分册 | 维度 | 核心问题 |
|------|------|----------|
| `01` | **产品定位与租户商业模式** | 自助注册即建租户 vs 企业级/合规定位；平台管理员与租户管理员的权责边界；套餐（plan）模型；获客与开通流程 |
| `02` | **能力闭环与业务规则** | 模型接入 → Prompt → 知识库 → Agent → 工作流 → 插件 六段链路是否闭合；能力间的引用与复用关系；自动化能力的真实边界 |
| `03` | **成本、计量与配额** | 成本驱动因素（Token/存储/调用次数）是否有对应约束；计量数据是否可用于成本分摊与计费；平台公共资源的成本归属 |
| `04` | **协作、权限与数据生命周期** | 租户内多用户协作与资源可见性；用户与租户的基数关系；数据导出与可移植性；软删除/留存/注销的合规自洽性 |

每个分册统一结构：`结论 → 问题清单（严重度/证据/根因/业务影响）→ 改进建议（含替代方案与权衡）→ 验收标准`。

## 3. 方法：证据驱动 + 复核撤销

沿用既有评审已验证有效的方法论，不降标准：

1. **并行探查**：按维度派 3 个只读子代理（禁止写文件），第四个维度自查。
2. **证据标准**：每条结论附 `文件:行号` + 代码片段；**禁止"可能存在"类推测**。
3. **复核阶段**：逐条回读源码验证。重点核查四类误判——
   - 业务规则是否真的缺失，还是由**上层流程**已保证（如归属校验在前置查询中完成）；
   - 配置项/字段是否真的**无消费方**（定义 ≠ 使用）；
   - 是否存在**对照点**（同一能力在某模块有、在另一模块无），对照证据比统计数字更有说服力；
   - 计数准确性（本机 Bash `grep` 有静默返回 0 的已知失真，一律改用独立检索工具并交叉验证）。
4. **主动撤回**：报告专设「交付前撤销的指控」一节，逐条说明撤销原因。
5. **结论分级克制**：只列**确信**的社区标准（OWASP、12-Factor、SaaS 多租户成熟度模型、TOGAF 业务架构原则等），不编造条款编号。

## 5. 已初步确认的锚点事实

以下三项已在方案阶段核实，作为本次评审必要性的依据（最终结论以评审为准）：

| 事实 | 证据 | 业务含义 |
|------|------|----------|
| 配额仅覆盖"资源数量"，不覆盖"资源消耗" | `services/quota.py:24-51` 仅校验 `max_users`/`max_models`；`token_usage` 表有记录但无消费方参与配额 | Token 成本不受平台约束，"配额管控"名不副实 |
| 全库无任何自动触发机制 | `cron\|schedule\|trigger\|webhook\|celery beat` 在 `backend/app` 零命中 | 号称"自动化工作流"，实际只能人工点击执行，业务价值受限 |
| 套餐硬编码 + 双通道建租户 | `services/user.py:79-82` 硬编码 `plan="free"/max_users=10/max_models=5`；`api/auth.py:73` 自助注册与 `api/admin.py:52` 管理员建租户并存；`models/tenant.py:18` `plan` 为自由字符串、无套餐定义 | 配额调整需改代码，无法运营；租户开通流程定位摇摆 |
| 用户与租户强绑定 1:1 | `services/user.py:70` 邮箱唯一性为**全局**校验（未按租户过滤） | 同一人无法归属多个租户，制约集团型/多客户场景 |
